# Issue 191: shuffled-label image benchmark pilot

## Decision

**No-go for claiming a 100% pass bar is deliverable.** This pilot did not produce a
passing reference for either track. It also did not test a model near the 10 million
parameter ceiling, so it does not establish that a passing reference is impossible.
Issue #194 should defer release until it either funds a near-limit training search and
publishes a passing reference, or changes the scope to a benchmark with a validated
pass bar. A 100% score on these same public 70,000 examples rewards memorization, not
generalisation to unseen images.

The reproducible preparation command is:

```sh
uv run mnnc download-mnist --output data
uv run mnnc download-fashion-mnist --output data
uv run python scripts/pilot_shuffled_labels.py --data-root data --output-root data/shuffled-labels
```

For each dataset, a fresh `numpy.random.Generator(numpy.random.PCG64(191))` is
created (NumPy 2.5.4 in this run). The shuffled target vector is
`rng.permutation(source_labels)`, preserving the source label counts while assigning
labels to different examples. A fresh-uniform comparison is then generated by the
same generator with `rng.integers(0, 10, size=70000, dtype=numpy.int64)`. Thus the
uniform labels are independent draws and are not forced to have equal counts. The
script also records source cache, output cache, and source file hashes in its JSON
report.

## Duplicate inputs and constant baselines

Exact pixel-byte duplicate analysis found 70,000 unique inputs and zero duplicate
groups on each track. Therefore no deterministic input-to-label function is blocked
by two identical inputs receiving different labels in this frozen set.

The constant classifier that always predicts the most common generated label gives
the following actual baseline over all 70,000 evaluated examples:

| Track | Permuted-label counts | Permuted-label baseline | Uniform-label counts | Uniform baseline |
| --- | --- | ---: | --- | ---: |
| MNIST | `[6903, 7877, 6990, 7141, 6824, 6313, 6876, 7293, 6825, 6958]` | 11.2529% | `[6992, 7022, 7008, 6900, 7056, 6998, 7021, 6973, 7098, 6932]` | 10.14% |
| Fashion-MNIST | `[7000, 7000, 7000, 7000, 7000, 7000, 7000, 7000, 7000, 7000]` | 10.00% | `[6992, 7022, 7008, 6900, 7056, 6998, 7021, 6973, 7098, 6932]` | 10.14% |

These values are the majority-class baseline, not a random-guessing expectation.

## Reference training attempt

Both attempts used the existing supervised image classifier trainer with seed 0,
normalised pixels, Adam at learning rate `1e-3`, batch size 128, and 20 epochs. The
architecture was `[784, 64, 10]` (50,890 parameters). Training inputs and labels came
from the full shuffled-label cache. The artifact was loaded from its on-disk
`config.json` and `model.pt` and evaluated with the public `mnnc evaluate` command,
which checks all 70,000 examples and uses the benchmark's 100% threshold.

The training call for each track was:

```python
from pathlib import Path

from minimal_nn_competition.examples.classifier_submission import train_classifier

train_classifier(
    data_path=Path("data/shuffled-labels/mnist-shuffled.pt"),
    output_dir=Path("models/pilot-mnist"),
    benchmark="mnist",
    epochs=20,
    batch_size=128,
    learning_rate=1e-3,
    device_name="auto",
    seed=0,
    normalise=True,
    name="pilot-64x20",
    author="issue-191 pilot",
)
```

For Fashion-MNIST, substitute `fashion-mnist` for the dataset and benchmark name,
and `models/pilot-fashion-mnist` for the output directory. Evaluate with
`uv run mnnc evaluate mnist models/pilot-mnist --data-path
data/shuffled-labels/mnist-shuffled.pt` and the equivalent Fashion-MNIST command.

## Limits and interpretation

This was a reproducible low-capacity pilot, not a search over the full allowed model
space. Its failure is evidence that a small conventional MLP does not solve either
random-label task; it is not evidence that all models within the limits fail. An
information-counting reference for 70,000 independent ten-way labels is
`70,000 * log2(10) ≈ 232,535` bits. That counts the information in one assignment; it
is not a proven lower bound on the size of a particular ReLU MLP, nor does it account
for how efficiently the fixed image set can be encoded by its weights.

Reproduction requires the pinned raw files, PyTorch and NumPy versions above, and
the repository's training/evaluation code. Raw input data are pinned by the four
checksums per dataset; labels are generated only by the stated ordering, PCG64 seed,
and NumPy version. Training time and learned checkpoint bytes can vary with hardware
and library kernels. The score is evaluated on the same public 70,000 examples used
for training, so it measures exact-set recall rather than held-out generalisation.
